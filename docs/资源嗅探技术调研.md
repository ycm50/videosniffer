## 二、资源嗅探的四种技术路线

### 路线 A：浏览器/WebView 请求拦截（最常用）

**代表：cat-catch（浏览器扩展）、xm0625/VideoSniffer（Android）**

浏览器扩展（cat-catch）：
- MV2 用 `chrome.webRequest.onSendHeaders` + `onResponseStarted` 监听 `<all_urls>` 的所有请求
- **两阶段判定**：
  1. **请求阶段**（onSendHeaders）：用用户配置的正则规则匹配 URL，命中则提取正则捕获组还原真实媒体 URL
  2. **响应阶段**（onResponseStarted）：收到首个字节后检查响应头 `Content-Type` / `Content-Disposition` / `Content-Length` 判定资源类型
- 扩展图标显示数字角标，支持自动下载

Android WebView（VideoSniffer）：
- 用 `WebViewClient.onLoadStarted` 回调捕获页面所有请求 URL（对应 shouldInterceptRequest 思路）
- `shouldOverrideUrlLoading` 检查 URL 扩展名是否为视频格式
- 注入 JS 自动点击播放按钮/自动播放 video/audio 标签，逼出真实资源请求
- 关键点：**WebView 需要设置 iPhone UA**（很多站点对移动端返回不同资源）

### 路线 B：本地代理抓包（桌面端主流）

**代表：putyy/res-downloader**

- 原理与 Fiddler/Charles/DevTools 相同：软件启动本地 HTTP(S) 代理（如 `127.0.0.1:8899`），设置系统代理为它
- 所有流量经过代理，按 Content-Type/URL 规则筛选出视频/音频/m3u8/图片资源
- 需要安装信任证书（MITM 解密 HTTPS）
- 对 Desktop App 流量也能抓（如微信视频号、小程序）

### 路线 C：无头浏览器 + 网络监听

**代表：hjdhnx/pup-sniffer**

- Puppeteer 驱动 Chrome，加载页面
- 通过 DevTools Protocol 监听 `Network` 事件 / 页面级 MutationObserver 捕获 video 元素、MediaSource
- 暴露 HTTP API：`GET /sniffer?url=...&mode=0|1&is_pc=0|1`，支持自定义正则、排除正则、注入脚本
- 适合服务端集中嗅探

### 路线 D：解析站点专用 API（最稳定）

**代表：hanime-hunter、HanimeTV**

针对 hanime 站点，直接调站点自身接口拿流地址，比通用嗅探稳定得多（见第四节）。

## 三、核心判定逻辑（如何认定一个 URL 是视频）

综合 VideoSniffer 和 cat-catch 的源码，判定顺序：

1. **URL 扩展名**：`.m3u8` `.mp4` `.flv` `.mpeg`（视频扩展名单，VideoSniffer）
2. **Content-Type**：
   - `application/vnd.apple.mpegurl` / `application/x-mpegurl` → m3u8
   - `video/mp4` / `application/mp4` → mp4
   - `video/x-flv` → flv
   - 注意：很多站点 m3u8 返回 `application/octet-stream`，需兜底
3. **Content-Disposition**：响应头带 `filename="..."` 时按附件名判定
4. **Content-Length / Content-Range**：解析大小（大小阈值过滤，如 <1MB 一般不是视频）
5. **正则规则**：用户/内置正则命中 URL 模式（cat-catch 核心能力）
6. **资源类型**：浏览器 webRequest 的 `type == "media"` 直接放行

### VideoSniffer 完整检测流程（`VideoSniffer.java` `WorkerThread.detectUrl`）

```
捕获URL → HEAD请求拿真实URL+响应头 → 无Content-Type则重试(最多3次)
→ detectVideoFormat(url, contentType) 判定格式
→ m3u8 则解析时长(>0 才算有效)；否则取 Content-Length 大小
→ 加入 foundVideoInfoMap（按URL去重）
```

### M3U8 有效性验证（`M3U8Util.figureM3U8Duration`）

```
下载 m3u8 文本
→ 遇到 #EXT-X-STREAM-INF 说明是 master playlist，递归进入子 m3u8
→ 累加 #EXTINF 时长
→ 总时长 <= 0 判定为无效资源
```

## 四、hanime 站点专属技术细节

### 4.1 hanime1.me 下载流程（hanime-hunter `hanime1me.go`）

```
1. 解析 watch URL 的 ?v= 参数 → vid
2. 抓取 watch 页，解析 #video-playlist-wrapper 容器 → 标题 + 分集链接列表（a[href*="watch"]）
3. 对每集请求：GET https://hanime1.me/download?v=<vid>
4. 解析 table.download-table 下所有 <a download="文件名"> 标签
5. 文件名格式含清晰度：用正则 [^/]+-\d+p 提取（如 xxx-1080p → 1080p）
6. 对下载链接发 GET 拿 Content-Type 得到 ext、Content-Length 得到 size
   （Content-Type 是 octet-stream 时按 mp4 处理）
```

> 结论：hanime1.me **不需要嗅探**，直接解析下载页表格即可拿到 mp4 直链。

### 4.2 hanime.tv 下载流程（hanime-hunter `hanimetv.go` + HanimeTV）

```
1. 从视频页 URL 路径取 slug：/videos/hentai/<slug>
2. 请求 JSON API：GET https://hanime.tv/api/v8/video?id=<slug>
3. 解析 JSON：
   - HentaiFranchise.title / slug
   - HentaiFranchiseHentaiVideos[]（分集 slug 列表，用于整季）
   - VideosManifest.Servers[0].Streams[] → 每个 stream 有 {id, url, height, size}
4. 流地址是 m3u8，按 height 映射清晰度（1080p 被跳过，可能是 bug/付费墙）
```

### 4.3 m3u8 下载细节（hanime-hunter `downloader.go`）

```
- 用 github.com/grafov/m3u8 解析 master → media playlist → segment URI 列表
- 读取 playlist 中 Key 的 URI 拿 AES-128 key 和 IV
- 20 并发下载 .ts 分片，AES-CBC 解密（crypto.go 的 AESDecrypt）
- 生成 "file '0.ts'" 格式的 fileList.txt，交给 ffmpeg MergeToMP4 合成 mp4
- 单视频下载支持 Range 断点续传（bytes=N-）
```

### 4.4 HanimeTV（Python）补充接口

- 搜索：`POST https://search.hanime.tv/`（JSON: search_text, tags, order_by...）
- 详情：`GET members.hanime.tv/api/v5/hentai-videos/<slug>`（需 session token）
- 下载：`GET mapi.htvanime.com/api/v4/downloads/<id>`（需登录 + x-signature 请求头）
- 登录：`POST mapi.htvanime.com/api/v4/sessions`（body: burger=email, fries=password；需 x-claim / x-signature 头）

## 五、针对 Android 项目的落地建议

项目状态：Kotlin + Gradle，包名 `com.hanime1`，目前只有 Android Studio 模板代码。

### 推荐方案

1. **首选路线 D（专用 API）**：直接实现 hanime1.me 的 `/download?v=` 下载页解析（逻辑完整可参考第四节），比通用嗅探稳定
2. **辅助路线 A（WebView 拦截）**：WebView 内实现 `shouldInterceptRequest` / `onLoadStarted` 捕获请求 + HEAD 请求验证 Content-Type，参考 VideoSniffer 思路改 Kotlin
3. **Android 11+ 文件落盘**：建议用 MediaStore（Downloads collection），避免存储权限问题
4. **m3u8 下载**：hanime.tv 流需要 master/media playlist 解析 + 分片下载 + AES-128 解密 + ffmpeg 合并；Android 上可打包 ffmpeg 二进制或走服务端

### 关键注意事项

- WebView 嗅探必须配置合理 UA（iPhone UA 常能拿到更友好的移动资源）
- 下载需携带 Referer / Cookie 等防盗链请求头
- 防抖与去重：同一 URL 只处理一次，避免重复抓取
- 超时与重试：hanime-hunter 对每段下载重试 10 次，失败随机 sleep 0.9~3s 防限流
